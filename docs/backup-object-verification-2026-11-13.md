# 对象暂存与提交前引用门禁（2026-11-13）

本轮在内部数据库事务原语上接入对象暂存及提交前校验，新增 restore_objects.go、restore_references.go 和测试。未提供整体 apply 入口、发布对象命名空间、开放生产目标、提交、推送、合并或部署；现有持久操作状态没有被推进为 ready_for_cutover 或 completed。

## 对象暂存

- 只接受已认证 VerifiedPackage，持有包读取句柄后取得固定对象目录和绑定。通过安全文件驱动的目录身份与祖先关系拒绝对象暂存目标与源包暂存目录重合或包含；目标必须预先存在、通过私有权限检查且为空。
- 在目标句柄下创建本轮独占的随机私有 generation，写入 operation_id、backup_id 和 package_sha256 所有权记录。这里复用安全 BackupTemp：业务层不拼接宿主路径或递归删除配置路径。
- 原对象 key 只作内存索引；落盘仍使用 `object-<opaque-id>` 平面名称，不把未经转换的 key 当目录。成功返回持有 generation 的内部句柄，用原 key 查找其内容。此布局是待发布暂存布局，现有应用 LocalFS 根目录不能直接当作已恢复业务命名空间使用。
- 写入前检查剩余空间；复制时再次比较大小/SHA-256，完成后从目标回读并再次比较。所有 manifest 对象都复制，包括没有数据库引用的封面、字体或其他对象。空间检查不是配额预留，中途 I/O/配额失败仍走清理。
- 活动读取句柄阻止清理；关闭只移除本次创建的 generation，并由驱动检查原目录身份、权限、链接及同步结果。清理失败返回稳定 CleanupFailure 和不含原始 key 的暂存引用；不宣称物理安全擦除。

key 索引与对象元数据为 O(对象数)，内容保持流式。没有对百万对象或大容量做性能承诺，也没有新增 S3 或 Windows 安全文件驱动。

## 数据库提交前门禁

restoreObjectDatabasePhase 先拒绝非法数据库目标和展开预算，再暂存对象；在整个数据库子步骤期间持有 generation 读取句柄。数据库事务仍按上轮可信基线/COPY 路径加载，在安全版本更新和 COMMIT 前检查：

- 书籍的激活源、章节所属源、书源映射必须属于书籍用户；进度和书签必须属于书籍用户；章节覆盖及失败记录不得跨越用户边界。
- 本地书的激活源必须是同一用户的 type=3/local:// 虚拟源，active_book_url 必须对应本书；本地章节属于该激活源，可读章节的 local 地址与书 ID、chapter_index 对应。
- 本地进度和书签引用的索引必须能在激活源的可读目录中找到。
- 每个本地可读章节都必须有 `local/<book-id>/<chapter-index>.txt` 对象。通过 key 索引打开暂存内容，流式检查 UTF-8 并再次比对 manifest SHA-256。不会把原始上传文件 hash 当成拆章对象 hash，也不会拉取外部封面 URL。

任何门禁失败都使本轮新建结构及数据回滚。确认失败/回滚后清理本轮对象；如果数据库 CommitUnknown 或回滚不能确认，则保留 generation 并返回其句柄，供后续状态核对，不能自动删除可能已被数据库引用的对象。成功也保留 generation，等待密钥校验、对象发布和人工切换门禁。数据库局部成功不等于整体恢复成功。

仍未实现所有字段的业务语义校验，例如在线书的跨源目录迁移、字符偏移与原文长度的完整对应、任意自定义设置中的对象引用；已保存的其他对象会完整保留，但不能称为所有资源引用均已验收。header 内容仍有待真实密钥解密验证，合成数据库夹具中的加密 header 明确不可解密。

## 验证

1. Windows backup/migration/storage 三目标包：34 个顶层、130 个含子测试通过事件，0 失败/跳过；日志 `.toolchain/backup-objects-windows-final.jsonl`。目标包 vet 通过。Windows 本轮覆盖纯模型与既有拒绝能力，不代表 Windows 原生对象暂存可用。
2. Linux 三目标包真实 race：52 个顶层、148 个含子测试通过事件，0 失败/跳过/竞争报告；日志 `.toolchain/backup-objects-linux-race-final.jsonl`。非 root、无网络、源码/docs/模块只读。
3. Linux 安全 LocalFS 测试实际复制及回读对象，验证源/目标重合拒绝、非空目标拒绝、活动 reader 阻止清理、最终无残留、取消不写入，以及源对象在认证后被同一测试用户改写时摘要拒绝并清理目标。源目录未被错误清理。
4. 独立 PostgreSQL 16.15 集群的数据库/对象测试通过：2 个顶层、10 个子测试，共 12 个通过事件，0 失败/跳过。有效样本含两个用户、本地书及两个实际章节对象；通过暂存 key 索引读取恢复后的中文/emoji 正文。缺少第二本书对象、错误 active_book_url、跨用户书源三个样本均通过外层包及数据库类型/外键检查，但在本轮引用门禁被拒绝，随后数据库 pristine、对象目标为空。
5. 真实测试继续包含上一轮后段外键错误、序列加载后的整数溢出、已有目标拒绝及提前取消，未放宽断言。记录 `.toolchain/backup-restore-db-28cb85d2423f/result.json` 和 tests.txt，两个临时容器清理均为 true。测试只有自有标签、无外网/宿主端口、数据库数据 tmpfs，合成源副本及暂存数据随测试清除；没有访问业务实例。此组 integration 未启用 race，race 是上述独立回归。
6. 单测覆盖成功和提交未知时保留对象、回滚未知时保留对象、确认失败后清理、清理失败保留引用、读回字节篡改/截断/超长拒绝。未知 COMMIT/回滚分支是策略单测，未声称已做真实网络断开故障注入。
7. 65 项契约模型检查及 16 份冻结摘要匹配；DDL、OpenAPI、历史迁移、冻结契约未修改。

首次 Linux/真实数据库运行被驱动拒绝，原因是新增测试夹具没有显式把临时根设置成 0700；已修正夹具而未放宽驱动。失败日志 `.toolchain/backup-objects-linux-race.jsonl` 与 `.toolchain/backup-restore-db-122287292b22` 保留，未计为通过；失败轮两个自有容器也已清理。

## 下一步与边界

当前对象 generation 仅有内部生命周期和所有权记录，尚未写入可恢复的持久操作阶段或完成标记。Empty 检查不构成跨进程独占租约；没有依赖它授权业务切换。下一步先补齐控制/目标排他锁、计划和位置身份的重验、generation 引用的持久登记及中断收敛，再接入真实 header 密钥验证和对象发布。必须先完成这些门禁，才能把本子步骤纳入整体 apply 或产生 ready_for_cutover 报告。

当前仍是隔离实验，未启动恢复实例，未修改部署或自动切换服务。
