## 误报、已覆盖或保留契约

| 审计项 | 复核结论 |
|---|---|
| publish defer 次序错误 | 误报。原代码先注册 Unlinkat 后注册 Close，LIFO 实际先 Close 后 Unlink；附件展示的修复顺序与原代码一致。不调换。正常路径再次 Close 的忽略错误不构成其所述清理漏洞。 |
| pairedUnicodeEscapes 引号/代理项边界 | 误报。扫描器跳过转义字节及完整代理对；它只做 Unicode 前置检查，JSON语法另由 exactValue/Decoder 拒绝。附件最后也承认其示例为非法JSON且会被拒绝，不重复实现整个JSON解析器。 |
| expires -1 缺 no-cache | 误报。已有镜像验收验证 no-cache；no-store/must-revalidate 不是当前入口要求。登录限流命名 location 缺 expires 不等于丢失 server 安全头。 |
| 生成 Handler 默认纯文本错误 | 当前业务入口已有 HandlerWithOptions JSON ErrorHandler 注入。保留生成代码，不手改模板输出。 |
| go.sum 中旧 /go.mod 行 | 不构成引用旧源码版本的证据；不删除校验行，不在本轮变更依赖。 |
| 替换规则400/422及设置422/code不一致 | 属已有契约技术债。保持现有行为及契约测试，下一API版本评审时统一。 |

| worker Probe 与串行 Eval 竞争 | 确认已知就绪可用性边界。需设计控制通道或有超时的活跃租约证据，不能简单把所有忙碌当健康；独立worker仍显式opt-in。 |
| 正则重复编译/超时 | 重复编译确有开销；RE2并无回溯型灾难，未有压测证明本项目P2级CPU问题，附件 transform.go 路径也不对应当前文件。后续基准测量后设计容量/字节双限缓存，不以LRU代替时间/输入预算。 |
| Unix socket 路径长度与清理 | Linux net.ListenUnix已对超长路径报错，锁文件清理已有句柄关闭/保留规则；显式配置期长度报错仍是可用性改进，非已证实安全绕过。后续统一父子进程校验，不盲用100字节魔数。 |

| COPY行8MiB | 明确 fail-closed 容量边界；本轮不提升内存上限，待极端JSONB样本和容量测试。 |
| guard 持锁慢I/O/未来心跳 | 持锁事实成立，未来执行CLI心跳竞争是待设计风险。不能只解锁而丢失对象句柄、guard生命周期或一次性写入约束。 |
| 普通LocalFS目录fsync | 掉电目录项耐久性限制成立，灾备安全驱动已有单独实现。未来需设计同步失败后的提交未知/补偿语义，不能仅加fsync并把已写文件当未提交删除。 |
