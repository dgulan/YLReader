# 同源目录重排的状态保护

不改冻结DDL/公开API。网络抓取仍在事务外；发布事务先锁源配置并验证版本，再按既有顺序锁书，复核书类型/活跃源/活跃URL、映射URL及抓取前旧目录行ID快照，拒绝过期抓取。普通进度写入也会触发book版本递增，因此不能将book.version变化一概视为目录变化；必须读取锁后最新用户状态。旧目录与用户状态必须在删除前读取；非活跃源预览不移动进度/书签/覆盖。

旧的可读index所指URL变更或消失时，视为位置语义变更。引用优先保留同index同URL，否则只能定位到新目录中唯一的同源完整URL；不按标题/编号模糊匹配，不把无目标进度夹到别的章节。已存进度保留char_offset、ratio、client_updated_at、device_id，更新index/章节元数据/百分比并自增version；无持久进度则建立version=2的默认新目录起点，避免旧合成version=1客户端静默写入旧index。沿用UpdateTOCMeta的数据库触发器递增book.version，以使离线章节上下文失效，不再额外递增一次；纯追加和原位置未变的刷新不制造进度版本冲突。

书签保留ID、偏移、标题、摘录、备注及创建时间，只移动index。锁定书签行，采用不占用旧/新index的临时正整数索引分两阶段更新，支持互换且避免非延迟唯一约束冲突。无法唯一定位或最终位置/偏移碰撞时，整笔刷新失败，不丢注释、不合并书签。

冻结schema明确刷新不移动单章覆盖。若新目录仍覆盖其index但该index的URL含义改变，拒绝整个刷新；越界仍按原约定标为stale，不私自移动覆盖。已标stale的在范围内记录也不静默改含义。

目录替换、状态重定位、版本及同步时间在同一事务提交，任一步失败保留旧目录及全部用户状态。进度写入已有书锁；新建书签/覆盖也使用同一书锁，防止发布中插入未纳入快照的记录。按ID删除书签通过行锁与原位更新保持删除语义，不通过删除再插入重建书签。

正文缓存及预热同时核对目标完整URL，旧缓存缺少该字段视为未命中；并发的旧预热最多导致一次缓存未命中，不得把旧index的正文交给新章节。book.version用于离线上下文失效，缓存URL校验不依赖读取book版本的时序。

测试须覆盖重排、索引互换、偏移/注释保留、旧进度版本冲突、无目标/歧义/覆盖阻挡回滚、数据库写入失败回滚、抓取期间并发进度更新、非活跃预览及追加不变。未携带目录版本的旧客户端在刷新完成后才发起的新建书签/覆盖，现有API无法完整识别其旧index含义；该限制需要后续契约设计，本轮不宣称已解决所有陈旧客户端写入。
