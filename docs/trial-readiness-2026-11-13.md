本轮在进度审计后继续处理网络配置和备份恢复设计；没有启动容器、连接数据库、创建备份、恢复数据、合并 PR 或部署。

## 已完成与验证

- Compose 的 app:8080 和 frontend:5173 绑定 127.0.0.1；Redis/PostgreSQL 不发布宿主端口。内部服务名及已有卷名保持不变。
- 使用公开 dummy 环境执行 `docker compose --env-file scripts/compose-check.env config --quiet` 成功；解析 JSON 后检查两个应用端口均为回环、两个数据服务没有 published ports，全部通过。仅处理内存中的展开配置，不打印凭据。
- 部署说明同步默认网络边界。未对运行中容器应用变更，未测试真实宿主防火墙；不能声称既有实例的网络暴露已消失。
- 备份 Draft 新增第 8 节：age v1/X25519 加密候选、tar 条目约束、完整认证后才使用明文、存储能力接口语义、实例和控制区配置、计划摘要、CAS 状态和崩溃处理。
- PostgreSQL custom archive 是逻辑备份，不是物理备份；已修正文案。不将 `--no-owner`、`--no-acl` 或 TOC 白名单称为恶意 SQL 隔离机制。

## 下一开发门禁

备份草案尚未冻结。先用专用隔离 PostgreSQL 16 集群完成最小原型：从当前权威 schema 生成含两用户、本地章节、进度、书签、header 信封和任务的确定性测试库，导出后恢复到另一空库，确认扩展预配置、非超级用户权限、触发器及外键顺序。失败时保留源库和脱敏证据，不升级权限或跳过约束使测试通过。

原型通过后固定官方 age 实现版本并完成互操作/篡改样本测试，确定容量预算和完整 manifest/配置结构，更新架构与冻结记录；之后才进入恢复业务实现。原型若无法在受限权限下安全工作，应重新评审为可信基线建库加结构化数据导入。

## 真实使用验收矩阵（待执行）

只用合法、自有或明确允许访问的内容和可重新导入的数据。每条结果必须记录提交、设备/浏览器、样本哈希、步骤、实际结果及脱敏证据；未执行不计通过。

| 场景 | 完成条件 |
|---|---|
| 合法书源整链路 | CSS、XPath、JSON、JS 的代表性允许访问样本各走搜索、加书、目录、正文和翻章；区分不支持规则、站点失败与本项目缺陷，不用静态可求值率替代 |
| TXT/EPUB | UTF-8/GBK/UTF-16 TXT 及无 DRM EPUB 覆盖目录、Unicode 正文、重启读取、进度、删除；原始文件另行保存，应用当前不留存原上传 |
| 移动端连续阅读 | 实际 Android/iOS 可用设备分别记录型号、系统和浏览器；连续阅读至少 1 小时，覆盖主题字号、前后台、锁屏和翻章；记录卡顿和内存，截图尺寸不替代真机 |
| 多端进度 | 两设备同版本写入产生冲突，两种显式选择都核对服务端结果；未决冲突刷新不静默覆盖；换源后核对章内位置 |
| 断网与重连 | 预加载后断网，缓存章可读；未缓存章有明确提示；重连后同步并保留冲突选择。首次完全离线启动不计为已支持 |
| 恢复演练 | 由备份工具在新隔离目标恢复数据库和对象，核对正文/书签/进度/header，旧会话失效、任务不重放；错密钥、缺对象、进程中断均不能覆盖源数据 |
| 性能容量 | 按 architecture 第 9 节和 11.2 单独测 p95、并发正文、内存和泄漏；记录硬件及数据规模，不用串行 race 或单次导入耗时替代 |

真实移动设备和实际允许访问的书源需在执行阶段落实。本轮仅建立验收矩阵，未冒充这些场景已测试。
