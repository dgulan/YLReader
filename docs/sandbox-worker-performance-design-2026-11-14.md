# worker 资源与性能验收范围

沿用 ADR-021，公开契约、默认模式及资源限制不变。本轮只使用合成数据和专有离线临时容器，不部署、不接入真实书源或生产数据。

固定amd64最终worker镜像，128MiB、1CPU、pids64、无swap、只读、非root、无网络。分别运行1/4个worker；父测试进程独立限制512MiB、1CPU。进程内对照在相同父容器中运行，但不具备worker内存隔离；两种模式的总CPU/内存预算不同，不由吞吐比推断架构优劣。

先检查正确性再测量：短规则、256KiB/1MiB正文输入后返回长度、256KiB输出、含256个对象的结构化结果、20ms合成HTTP代理。每组预热8次、测量100次，客户端并发1/4/16，记录成功/错误分类、成功延迟p50/p95/p99、全体请求延迟、整组墙钟吞吐与GC/分配量。错误单列，不能通过只统计成功调用掩盖排队失败。离线合成HTTP不代表实际网络延迟。

单独测32MiB阈值附近输入，限制请求次数并记录失败与后续新调用恢复，不在父进程执行无界分配。输入阈值不是接受保证，若128MiB无法容纳，则记录可接受范围，不提高限制来隐藏失败。cgroup memory.peak为容器生命周期高水位，不可冒充每个请求峰值；无法读取时仅报告Docker采样最大值并明确非真实峰值。记录OOM事件及重启次数，正常负载不得无解释重启。

数据只用于本机合成基线；重复运行至少两轮，不能作生产SLA、用户容量或ARM性能结论。真实来源、长时稳定性、最大树及ARM原生验收仍独立保留。

第二轮补充父进程在途字节预算的验收：每次求值按 JSON 编码上界计 2 倍成本，默认预算为 2×输入上限（生产 64MiB），与 250ms 准入窗口共用；饱和沿用既有 `ErrSandboxTimeout`（504），不新增公开错误码、不无界排队。用 10MiB 紧预算、4MiB 输入与 600ms 慢 HTTP 验证“1 成功 + 其余在窗口内拒绝”，用 64MiB 预算、4×12MiB 验证最多 2 个在途；同时记录父容器 cgroup 峰值与 OOM 事件，确认拒绝路径不产生无界分配。admission 阶段在 edge 之后重启 worker，避免 31MiB OOM 的热堆污染预算结论。128MiB worker 只作为实验规格，生产规格按 operations 文档 <=256MiB 另行验收。
