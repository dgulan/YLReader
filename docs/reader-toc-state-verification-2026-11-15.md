# 同源目录重排状态保护验收

本轮完成目录刷新时既有进度、书签和正文缓存的保护，不改冻结公开API/DDL，不自动覆盖用户书源。本轮未部署、未提交、未推送，未操作已有阅读账号或生产数据库。

## 实现结果

- 抓取在事务外进行；发布时依次锁源配置、书籍、映射，核对源版本、活跃源/URL、映射URL及抓取前目录行快照。过期抓取返回现有422 relocation_failed，不覆盖已更新目录。
- 已有章节index的URL变更/消失时，进度与书签按同index同URL优先、否则唯一完整URL匹配重定位。保留进度偏移、比例、客户端时间及设备；递增进度版本，拒绝旧版本PUT。无持久进度时建立新目录起点version=2；纯追加不递增进度版本。
- 书签原位更新，保留ID、偏移、标题、备注/摘录及创建时间；两阶段临时index支持相同偏移书签互换。找不到唯一目标或最终位置冲突时，整笔刷新失败。
- 遵守冻结覆盖规则：不移动单章覆盖；在范围内却改变原章节含义时拒绝刷新，缩水越界继续标stale。非活跃源预览不改变活跃阅读状态。
- 新建书签/覆盖采用同一书锁；读取最新进度与锁定书签行后发布，避免遗漏事务期间的新建记录，也不通过删除重建导致已删除书签复活。
- 正文缓存和后台预热增加目标URL校验，旧payload无此字段自动视为未命中，避免目录重排或覆盖URL变化后复用旧索引正文。
- 目录、进度、书签、元数据与同步时间在一个事务内提交；book.version沿用UpdateTOCMeta的数据库触发器，不额外递增。

新增8项顶层测试（其中6项数据库集成）覆盖：URL重排/缺失/歧义、书签索引互换与字段保留、覆盖阻挡、旧进度版本冲突、无进度的初始版本、纯追加、抓取期间进度写入、书签/覆盖等待书锁、过期源/书籍/映射/目录快照，以及缓存与预热在同索引换URL后失效。数据库故障用隔离库专属CHECK约束在元数据更新阶段触发，验证已经执行过的目录替换、进度/书签移动和版本变更全部回滚，清理该约束。

首轮 `.toolchain/gemini-integration-9b5b668c84a9/` 有3项新增测试失败，保留原证据：错误地把book.version变化等同目录变化，并重复递增版本。复核schema发现TouchLastRead和UpdateTOCMeta均会触发book版本递增；改为目录快照与实际路由字段校验，沿用现有触发器。中间轮 `a7b1acff3bc4` 31项通过；最终轮包含映射行锁和加强的旧URL预热缓存用例。未过滤失败或降低进度/书签保留断言。

Windows service/repository/api普通测试通过；65项契约检查通过、16个冻结哈希匹配；gofmt与git diff --check通过。前端与真实远程站点本轮未重跑，不将后端定向回归等同完整发布回归。
