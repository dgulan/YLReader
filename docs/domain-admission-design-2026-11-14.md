# 统一出网域名限速契约 v1（2026-11-14）

状态：本轮内部实现契约。研究、DDL、43 个 API 操作及备份冻结文件均不变。本轮不部署。承接 Gemini 复核第 09 项的限流能力缺口，先交付域名层，书源 concurrentRate 的数字并发/窗口语义另行设计，不称其已完成。

## 范围和默认值

生产唯一 Fetcher 的 RoundTripper 在每次应用层 HTTP 尝试前申请预算，包含连接复用、Fetcher 重试、同域/跨域重定向与使用同一 Fetcher 的 JS 桥接；DNS/IP 连接级 SSRF 判定继续保留。入口 URL 和每个重定向目标仍须通过 URL 形态检查。Go Transport 在一次 RoundTrip 内部进行的连接故障自动重试共用该次预算，本契约不是逐数据包或逐 TCP 发送的严格线速限制。

同一规范化 hostname 共用一个预算，不区分用户、书源、协议和端口。ASCII 大小写、尾点、IDNA 等价域名合并；IP 地址标准化，IPv4-mapped 地址归一。不同子域名暂不合并到可注册域名；DNS 别名、同一 IP 的不同 hostname 亦不合并，不能宣称防止恶意多域绕过。

每个域名默认相邻准入至少 500 ms（2 次/秒，突发容量 1）。预算覆盖开始尝试，不是同时连接数：不阻止长响应重叠。每次等待最多 5 秒，并服从调用方更早的取消/截止时间。无预订队列，不保证 FIFO；未获准的等待者不占未来令牌，取消不退还已消耗预算。

## 存储与故障

配置 Redis 时复用正文缓存的地址、TLS、认证及 DB 配置，但限流不走缓存 miss/故障降级。原子 Lua 操作查看 PTTL：不存在则 SET PX 后准入，尚有 TTL 则返回等待毫秒数；没有 TTL 或非预期状态视为损坏并拒绝。键为版本化前缀加规范化 hostname 的 SHA-256，不含原 URL、路径或用户信息。状态自动过期；多副本同一 Redis DB 共享预算。Redis 状态丢失/主从切换可能重置预算，不宣称严格分布式流量证明。

没有配置 Redis 时只使用有界内存状态（最多 4096 域名），共享生产 Fetcher 实例；容量耗尽仅回收已过期条目，不能驱逐仍有效条目绕过预算。该模式不跨进程。Redis 已配置但断开、协议损坏或超时，一律拒绝出网，不回退内存，不自动重试准入失败。

存储或容量故障复用既有 ErrUpstreamError / 502 source_request_failed 映射，等待截止沿用 504 source_timeout；内部增加 ErrRateLimit 供判断，不增加公开错误码或变更 API。记录/返回错误不携带 Redis 回复或凭据。无论等待失败或目标无效，RoundTripper 均关闭请求体。预算后仍须通过 SSRF 连接检查；准入不是安全地址许可。

## 验证门禁

测试规范化等价域名、并行竞争和不同域名隔离、内存容量及过期回收、取消与故障拒绝、重试与重定向逐跳计费、请求体关闭；实际临时 Redis 验证 Lua 原子竞争与 TTL。仅有模拟客户端测试不足以证明 Redis 脚本可执行。不引入新的第三方依赖。

Redis 命令依据：[EVAL 原子脚本](https://redis.io/docs/latest/commands/eval/)、[PTTL 的 -1/-2 语义](https://redis.io/docs/latest/commands/pttl/)。
