# 抖音小说目录分页适配与边界

真实目录探测确认：首页与第二页均包含最新章节区和标有“正文”的分区，有13个分页选项，范围1–100至1201–1202，并有明确“下一页”链接。原源chapterList为id.list@dd，nextTocUrl为空；112项是12条最新章节和100条正文。不能把此现象当作引擎112项硬上限，也不能证明reader原软件已自动补齐整书目录。

保留原源不变，建立明确命名的适配副本，仅修改两项规则：

```json
{
  "chapterList": "//div[@id='list']//dt[contains(.,'正文')]/following-sibling::dd",
  "nextTocUrl": "//a[contains(normalize-space(.),'下一页')]/@href"
}
```

这是ruleToc内的差异，不是可直接导入的完整书源。chapterName/chapterUrl沿用原源。该适配基于观察到的页面结构，不绑定书籍ID或章数；不自动改写用户原规则，不为无分页规则的源猜测链接。所有回源继续经Fetcher，维持既有10秒总预算、20页上限、访问循环检测及部分页失败语义；若计数未达到验收期望，不能宣称目录完整。

补原创两页HTML测试：每页有最新章节区，适配仅选择正文，按页顺序合并，下一页循环不会重复请求；另验证原来无nextTocUrl时不会自动翻页。另发现EvalNextURL的CSS分支未像列表规则那样展开@选择器链，应复用splitSelectorChain顺序选择，不改变XPath/JS/网络能力，补嵌套分页容器与带@属性值的回归。

真实适配副本仅写入忽略目录，报告显式标注rules_modified=true。验收仅目录元数据，不读取正文；核对上游声明的1202项、URL去重、章节索引和编号覆盖（1–1192，另有无编号条目），期望数只属于本轮测试参数，不能写进产品逻辑。directory_integrity_verified只能代表这些明确的结构检查，不代表所有内容可读、真机或发布门禁通过。
