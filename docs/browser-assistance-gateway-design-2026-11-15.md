# 浏览器辅助HTTP Gateway实现范围

本轮为协议组件增加真实HTTP控制通道，仍不注册生产配置、不接入Fetcher、不启动solver。浏览器全部流量的网络隔离/代理尚未实现，因此不得把控制通道当作已完成的浏览器SSRF防火墙。

管理配置固定Endpoint（/v1、显式端口、无userinfo/query/fragment）、私有/回环控制IP白名单、允许的精确HTTPS目标origin。源JSON/请求不能更换控制地址。控制DNS每次解析结果必须全部落在白名单，再拨解析后的IP，保留TLS默认校验；不读取环境代理、不跟随重定向、不自动重放POST控制请求、不发送认证/Cookie/代理参数。

Exchange只接受三个字段cmd=request.get、url、maxTimeout，拒绝重复/变体字段及超额长度；最多32KiB输入、1MiB响应、32KiB响应头，默认5秒/上限30秒总预算含DNS/连接/正文读取，maxTimeout不能超出剩余预算。请求前目标DNS检查拒绝所有私有/保留IP，但这只是初次检查，浏览器后续DNS/跳转/子资源必须另由强制出网代理和网络策略约束。

测试使用本地模拟HTTP服务，覆盖固定端点、私有控制地址显式授权、控制DNS漂移、目标DNS拒绝、非法payload、重定向不跟随、错误状态/编码、响应超长、慢体/取消、预算、一次POST及secret错误脱敏。生产默认行为和公开契约不变，未通过浏览器网络隔离门禁前不得启用。

HTTP请求取消只保证本端控制连接关闭，不保证真实solver已销毁浏览器或中止其网络流量。该生命周期必须后续通过真实solver的会话/任务清理及容器限制单独验收，不能把模拟服务的context退出当作实际Chrome回收证明。
