# 实际前端镜像验收设计

保持公开API/DDL不变，不部署/提交/推送。通过现有frontend/Dockerfile构建本地amd64镜像，使用镜像自带配置和dist，不把本机文件挂载覆盖它们，不以旧nginx镜像挂载新dist冒充当前镜像。记录镜像ID与配置/静态资源摘要，构建上下文排除测试产物、截图、报告及本机.env文件。

首次离线构建在可变docker/dockerfile:1语法镜像取令牌时失败。前端Dockerfile仅使用标准多阶段指令，改用内置解析器，与worker既有处理一致；基础镜像摘要、依赖锁文件和安装命令不变。若仍缺构建缓存，必须单独记录构建限制，不能把旧镜像测试写成当前完整构建通过。

独占临时Docker网络/PG/Redis/当前Linux后端和前端容器，宿主只发布127.0.0.1随机端口。使用原创TXT/EPUB与临时账号，从实际nginx同源入口运行严格阅读用例；保留pageerror、未处理拒绝及CSP违规空断言。临时资源按唯一标签清理，不连接已有实例或持久数据卷，不测试真机或TLS。

Docker Desktop的internal网络在本轮没有提供发布端口，首轮脚本因此在取端口时停止且清理完成。改用本轮独占bridge，只发布前端及API就绪控制的loopback端口；PG/Redis不发布端口。该bridge不是无网络环境，本轮只用原创本地样本、不调用外站，不将其描述为网络沙箱验收。

HTTP检查覆盖根入口、SPA深链、真实哈希资源和缺失资源；安全头需在正常及错误响应中存在，HTTP入口不错误启用HSTS。检查实际缓存策略，缺失静态资源不得被SPA回退伪装为200 HTML。若需修复，先保留失败证据再修改nginx；哈希资源可长期缓存，入口HTML必须重验证，避免旧入口引用已更换资源。以真实浏览器确认CSP不阻断阅读、管理页面及IndexedDB缓存。

登录限流在阅读完成后验证，避免消耗测试账号登录预算而干扰阅读结果；检查429状态与JSON形状。冷加载记录资源数量/总字节/请求时长，仅作为当前本机受控场景数据，不据单次结果给出容量或移动真机性能保证。amd64通过不替代arm64原生、生产TLS或正式发布。

修复前HTTP证据确认HTML/深链无重验证、哈希资源无长期缓存、缺失脚本返回200 HTML。使用独立index.html/assets位置和expires指令修正，不在子位置单独增加add_header而丢失父级安全头；404仍继承always安全头。

镜像首轮WebKit在手机参数会话的书架GET尚在途时直接page.goto进入阅读器，报告该GET访问控制pageerror。严格保留失败结果；正文阅读用例现先确认初次书架GET成功且接收完成，再开始阅读，仍断言所有pageerror/CSP违规为空。这项前置条件不证明在途书架GET整页跳转的异常已修复，该生命周期场景需独立复核。EPUB页面异常收集扩展到桌面与移动两会话。

首轮限流探测使用不存在账号，首次dummy Argon2初始化及校验在受限容器中耗时16.3秒，超过脚本15秒HTTP窗口。曾改为缺字段的JSON对象{}，后续代码复核确认它仍进入dummyVerify，不能称为无散列开销。最终改用语法错误的JSON，并要求未限流请求400、限流请求429，以nginx日志和JSON确认代理限流；不以此证明认证性能通过。失败轮的stdout/JSON及容器日志保留。
